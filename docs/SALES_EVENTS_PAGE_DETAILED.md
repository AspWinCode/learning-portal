# Детальное описание страницы «События» (Мероприятия)

Документ описывает страницу мероприятий для отдела продаж: хаб `/sales/events`, вкладку «События», создание мероприятий, регистрации лидов и действия по ним.

---

## 1. Общая структура

| Параметр | Значение |
|----------|----------|
| **URL** | `/sales/events` |
| **Роли** | admin, owner, sales |
| **Компонент-оболочка** | `SalesEventsHubPage` (`frontend/src/pages/SalesEventsHubPage.tsx`) |
| **Контент вкладки «События»** | `SalesEventsPageContent` (`frontend/src/pages/SalesEventsPage.tsx`) |

Хаб содержит **пять вкладок** (MUI Tabs):

1. **События** — мероприятия и регистрации (основной контент этого документа).
2. **Дожать на обучение** — лиды после посещения (post-visit).
3. **Повторно позвать** — повторное приглашение на мероприятие.
4. **Решили сразу** — лиды в статусе «решил сразу».
5. **Счета** — создание и отправка счетов.

Переключение вкладок — локальный state `tab`; при выборе «События» рендерится `SalesEventsPageContent` без Layout (Layout уже у хаба).

---

## 2. Вкладка «События» (SalesEventsPageContent)

Назначение: **мероприятия** (мастер-классы, дни открытых дверей и т.п.) и **регистрации лидов** на них. По каждой регистрации можно отмечать: подтвердил участие, пришёл, не явился, отменить запись.

### 2.1. Загрузка данных

При монтировании вызываются:

- `salesApi.listEvents('active')` — список **активных** мероприятий (статус `active`), сортировка по дате начала.
- `salesApi.listLeads()` — список лидов (для выбора лида при регистрации).

При выборе мероприятия в выпадающем списке (`selectedEventId`) вызывается:

- `salesApi.listEventRegistrations(selectedEventId)` — все регистрации по этому мероприятию (в т.ч. отменённые).

Ответ регистраций содержит для каждой записи объект `lead` (данные лида), если бэкенд подгружает связь.

### 2.2. Верхняя панель

- Заголовок: **«Мероприятия»**.
- Кнопка **«Зарегистрировать лида»** — открывает диалог регистрации; недоступна, если мероприятие не выбрано или нет свободных мест (при заданной вместимости).
- Кнопка **«Новое мероприятие»** — открывает диалог создания мероприятия.

### 2.3. Сетка контента (две колонки)

**Левая колонка (список мероприятий):**

- Заголовок «Список мероприятий».
- Выпадающий список **«Выберите мероприятие»** — все активные мероприятия из `events`; значение хранится в `selectedEventId`.
- Если мероприятие выбрано — блок с деталями:
  - Название.
  - Локация (или «Локация не указана»).
  - Дата и время начала (формат `dd.MM.yyyy HH:mm`).
  - Слоты: значение `capacity` (или «без лимита»); при наличии лимита — «занято X, осталось Y».

**Правая колонка (регистрации и аналитика):**

- Заголовок «Регистрации».
- Карточки-метрики (сводка по регистрациям выбранного мероприятия):
  - **Зарегистрировано** — число записей со статусом `registered`.
  - **Подтверждено** — число записей, в заметке которых есть тег `[confirmed]`; процент от зарегистрированных и цвет (success/warning/error по порогам 70% / 40%).
  - **Пришло** — тег `[came]`; процент к подтверждённым.
  - **Не явились** — тег `[no-show]`; процент от регистрации.
  - **Оффер** — среди зарегистрированных/пришедших лиды со статусом `invoice_sent` или `won`; процент от пришедших.
  - **Оплата** — лиды со статусом `won`; процент от оффера.

- Блок **«Узкое место»** (Alert): вычисляется этап с наименьшим процентом (подтверждение от регистрации, явка от подтверждённых, оффер от пришедших, оплата от оффера) и выводится рекомендация (например, «усилить напоминания», «добавить напоминания за 24ч/2ч» и т.д.).

- Кнопки **массовых действий** (для выбранных строк таблицы регистраций):
  - **Подтвердить (N)** — добавить тег `[confirmed]` выбранным регистрациям.
  - **Пришел (N)** — тег `[came]`.
  - **Не явились (N)** — тег `[no-show]`.
  - **Отменить (N)** — перевести регистрации в статус `cancelled`.

- **Таблица регистраций**:
  - Чекбокс «выбрать все» (только по строкам со статусом `registered`).
  - Колонки: чекбокс, Лид (ссылка на карточку лида `/sales/leads?detail={lead_id}`), Контакт (телефон), Статус, Действия.
  - Статус строки определяется по заметке регистрации (приоритет: `[came]` → «Пришли», `[no-show]` → «Не явились», `[confirmed]` → «Подтвердили», иначе «Записан»; при статусе регистрации `cancelled` — «Отменён»).
  - Для каждой строки со статусом `registered` в колонке «Действия»: кнопки **Подтвердить**, **Пришел**, **Не явились**, **Отменить** (кнопки «Подтвердить»/«Пришел»/«Не явились» отключаются, если соответствующий тег уже есть в заметке).

Чекбоксы позволяют выбрать несколько регистраций и применить к ним одно из массовых действий; после выполнения выбор сбрасывается, список регистраций обновляется.

## 3. Диалог «Новое мероприятие»

Открывается по кнопке «Новое мероприятие».

**Поля формы:**

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| Название | TextField | да | Заголовок мероприятия |
| Описание | TextField, multiline | нет | |
| Начало | datetime-local | да | Дата и время начала |
| Окончание | datetime-local | нет | Дата и время окончания |
| Локация | TextField | нет | Место проведения |
| Лимит мест | number | нет | Вместимость (capacity); пусто = без лимита |

Кнопки: **Отмена**, **Создать**.

При создании вызывается `salesApi.createEvent({ title, description, starts_at, ends_at, location, capacity })`. Даты передаются в ISO (например, `new Date(starts_at).toISOString()`). После успеха диалог закрывается, форма сбрасывается, список мероприятий перезапрашивается.

---

## 4. Диалог «Регистрация лида»

Открывается по кнопке «Зарегистрировать лида» (при выбранном мероприятии и наличии свободных мест).

**Поля:**

- **Лид** — выпадающий список всех лидов из `salesApi.listLeads()`; отображается как «ФИО (телефон)» (родитель/ребёнок или contact_name и телефон).
- **Заметка** — многострочное поле (необязательно), сохраняется в `note` регистрации.

Кнопки: **Отмена**, **Зарегистрировать**. Кнопка «Зарегистрировать» отключена, если мероприятие заполнено (`isEventFull`).

При отправке вызывается `salesApi.registerLeadToEvent(selectedEventId, { lead_id, note })`. После успеха диалог закрывается, список регистраций выбранного мероприятия обновляется.

Один и тот же лид не может быть зарегистрирован дважды на одно мероприятие в статусе `registered` — бэкенд вернёт ошибку «Lead already registered». Ранее отменённую регистрацию бэкенд восстанавливает (статус снова `registered`, обновляется заметка).

---

## 5. Логика статусов и тегов в заметке

Регистрация имеет статус: `registered` или `cancelled`. Дополнительно в поле **note** используются теги (без отдельной сущности «статус посещения»):

- **`[confirmed]`** — участник подтвердил участие.
- **`[came]`** — участник пришёл.
- **`[no-show]`** — участник не явился.

На фронте отображаемый «статус» строки (Записан / Подтвердили / Пришли / Не явились / Отменён) вычисляется так:

1. Если `reg.status === 'cancelled'` → «Отменён».
2. Иначе по содержимому `reg.note` (без учёта регистра): наличие `[came]` → «Пришли», `[no-show]` → «Не явились», `[confirmed]` → «Подтвердили», иначе → «Записан».

Бэкенд при действиях «Подтвердить», «Пришел», «Не явились» добавляет соответствующий тег в начало заметки (функция `_append_note_tag`: если тега ещё нет, то `"{tag} {note}".strip()`).

---

## 6. Действия по регистрации и последствия на бэкенде

| Действие на фронте | API | Что делает бэкенд |
|--------------------|-----|-------------------|
| Подтвердить | `POST /api/sales/events/{eventId}/registrations/{regId}/confirm` | Добавляет в note тег `[confirmed]`. |
| Пришел | `POST .../mark-came` | Добавляет тег `[came]`. Статус лида переводится в `demo`, при необходимости выставляется `post_visit_stage = "new"`. Создаётся авто-задача «После мероприятия: предложить курс» (если такой ещё нет), due через 24 ч. |
| Не явились | `POST .../mark-no-show` | Добавляет тег `[no-show]`. Создаётся авто-задача «No-show: реактивация и перенос», due через 24 ч. |
| Отменить | `POST .../cancel` | Статус регистрации → `cancelled`. |

Массовые действия на фронте — последовательный вызов тех же API по выбранным id регистраций (`Promise.allSettled`), затем обновление списка регистраций и сообщение об успехе/частичном успехе.

---

## 7. Вместимость (capacity)

- Если у мероприятия задано `capacity`, при добавлении новой регистрации бэкенд проверяет: число регистраций со статусом `registered` не должно быть >= capacity; иначе 400 «Свободных слотов нет».
- На фронте для выбранного мероприятия считаются `slotsUsed` (число `registered`) и `slotsLeft = max(0, capacity - slotsUsed)`. Кнопка «Зарегистрировать лида» отключена при `slotsLeft <= 0` (и отображается подпись «Слоты закончились» в диалоге).

## 8. API (Backend)

Роутер: `backend/app/routers/sales.py`, префикс по приложению (например, `/api/sales`).

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/events` | Список мероприятий. Query: `status_filter` (optional) — active/archived. Сортировка по `starts_at`. |
| POST | `/events` | Создание мероприятия. Body: EventCreate (title, description, starts_at, ends_at, location, capacity). Статус по умолчанию ACTIVE. |
| PUT | `/events/{event_id}` | Обновление мероприятия (EventUpdate). |
| GET | `/events/{event_id}/registrations` | Список регистраций по мероприятию (все статусы), по убыванию created_at. В ответе у каждой регистрации может быть объект lead. |
| POST | `/events/{event_id}/registrations` | Создание регистрации. Body: lead_id, note (optional). Проверки: мероприятие активно; при наличии capacity — есть свободные места; лид не зарегистрирован (или восстановление отменённой записи). |
| POST | `/events/{event_id}/registrations/{registration_id}/cancel` | Отмена регистрации (статус → CANCELLED). |
| POST | `.../confirm` | Добавление тега [confirmed] в note. |
| POST | `.../mark-came` | Тег [came], перевод лида в demo, авто-задача «предложить курс». |
| POST | `.../mark-no-show` | Тег [no-show], авто-задача «реактивация». |
| GET | `/leads/{lead_id}/event-registrations` | Регистрации лида по всем мероприятиям (для карточки лида и т.п.). |

Права: все перечисленные эндпоинты — роль `admin`, `owner` или `sales`. Для операций с регистрацией проверяется, что текущий пользователь — owner или admin по лиду (`_require_owner_or_admin(lead, current_user)`).

## 9. Модели данных (кратко)

**Event (мероприятие):** id, title, description, starts_at, ends_at, location, capacity, status (active/archived), created_by, created_at, updated_at.

**EventRegistration (регистрация):** id, event_id, lead_id, owner_id, status (registered/cancelled), note, created_at, updated_at. Связь с Lead — для отображения ФИО, телефона и статуса лида (оффер/оплата).

Уникальность: одна пара (event_id, lead_id) — одна запись (при повторной регистрации того же лида на то же событие бэкенд либо возвращает ошибку, либо восстанавливает отменённую запись).

---

## 10. Связь с другими разделами

- **Дашборд продаж** (`/sales` или аналог): карточки «Записано на мероприятие», «Пришло», «No-show» ведут на `/sales/events`.
- **Лиды** (`/sales/leads`): в карточке лида можно записать на мероприятие; со страницы событий по клику на лида открывается `/sales/leads?detail={lead_id}`.
- **Дожать на обучение** (вкладка того же хаба): лиды, отмеченные «Пришел», переводятся в статус `demo` и попадают в воронку «Дожать на обучение»; для них создаётся задача «предложить курс».
- **Повторно позвать** (вкладка того же хаба): лидов с тегом повторного приглашения можно массово переназначить на другое мероприятие.

---

## 11. Резюме

Страница **«События»** — это:

1. **Список активных мероприятий** с выбором одного и просмотром деталей (локация, дата, слоты).
2. **Создание мероприятий** (название, описание, даты, локация, лимит мест).
3. **Регистрации лидов** на выбранное мероприятие (выбор лида + заметка), с учётом вместимости и запрета дублей.
4. **Таблица регистраций** с отображением статуса по тегам в заметке (записан / подтвердил / пришёл / не явился) и ссылкой на карточку лида.
5. **Действия по регистрации**: подтвердить, пришёл, не явились, отменить — по одной или массово по выделенным строкам.
6. **Аналитика по выбранному мероприятию**: воронка зарегистрировано → подтверждено → пришли → оффер → оплата, с процентами и выделением «узкого места» с рекомендацией.

Бэкенд при отметке «Пришел» переводит лида в статус demo и создаёт задачу на дожим; при «Не явились» — задачу на реактивацию. Все изменения регистраций и лидов доступны только пользователям с ролью admin, owner или sales с учётом привязки лида к владельцу/админу.
