# Learning Portal — Процедура анализа каждого модуля

## Шаблон анализа функционала

Для каждого модуля выполнить в этом порядке:

### ШАГ 1: Сбор информации (10-15 мин)
```bash
# 1.1 Список endpoints
grep "^@router\." backend/app/routers/{MODULE}.py

# 1.2 Структура файлов
wc -l backend/app/routers/{MODULE}.py
wc -l backend/app/services/{MODULE}*.py
wc -l backend/app/schemas/{MODULE}.py

# 1.3 Модели БД
grep "class.*{MODULE}" backend/app/models.py
```

### ШАГ 2: Соответствие US → Реальность (15-20 мин)
| US ID | User Story | Endpoint | Файл | Статус |
|-------|-----------|----------|------|--------|
| US-X-01 | Описание | GET /api/... | routers/x.py:42 | ✅ / ❓ / ❌ |

**Статусы:**
- ✅ Реализовано и работает
- ❓ Реализовано, но требует проверки
- ⚠️ Частично реализовано
- ❌ Не реализовано

### ШАГ 3: Анализ каждого US (5-10 мин на US)
Для каждого US заполнить:

1. **API контракт** — точный Request/Response
2. **Реализованные сценарии** — какие из тестов работают
3. **Пробелы** — что не хватает или работает неправильно
4. **TODO** — конкретные задачи для исправления

### ШАГ 4: Итоговый отчёт (5 мин)
```
Статистика покрытия:
- User Stories: X/Y (%)
- Endpoints: X/Y (%)
- Сценарии работают: X/Y (%)
- Критерии приёмки: X/Y (%)

Приоритетные TODO:
- HIGH: ...
- MEDIUM: ...
- LOW: ...
```
