## Что такое деплой и что мы поднимаем

**Деплой** — это когда приложение не просто запущено у вас в папке, а доступно по адресу (на компьютере — localhost, на сервере — ваш домен).

Приложение состоит из трёх частей:

| Часть | Что это | Зачем |
|-------|--------|--------|
| **База данных (PostgreSQL)** | Хранилище: пользователи, ученики, оценки, программы | Все данные живут здесь |
| **Backend (API)** | Сервер на Python (FastAPI) | Обрабатывает логику, авторизацию, сохраняет в БД |
| **Frontend (сайт)** | Интерфейс на React + Caddy (веб-сервер) | То, что видит пользователь в браузере |

**Docker** — это способ запустить все три части одной командой, не устанавливая вручную PostgreSQL и не настраивая порты. Docker ставится один раз, дальше всё поднимается из `docker-compose`.

## Вариант 1: Деплой на своём компьютере (Windows)

Подходит, чтобы проверить, что всё работает, или пользоваться только с этого компьютера по `http://localhost`.

### Шаг 1. Установить Docker Desktop

1. Скачайте установщик: https://www.docker.com/products/docker-desktop/
2. Запустите установщик и пройдите шаги (можно оставить настройки по умолчанию).
3. В конце попросят перезагрузить компьютер — перезагрузите.
4. После перезагрузки откройте **Docker Desktop**. Дождитесь, пока внизу слева будет зелёный индикатор «Docker is running».
5. Проверьте в PowerShell (Win+X → «Windows PowerShell»):

   ```powershell
   docker --version
   docker compose version
   ```

   Должны появиться номера версий без ошибок.

### Шаг 2. Открыть папку проекта

1. Откройте папку вашего проекта (та, где лежат папки `backend`, `frontend` и файл `docker-compose.yml`).
2. В адресной строке проводника введите `cmd` и нажмите Enter — откроется командная строка в этой папке.  
   Или: Shift + правая кнопка мыши по пустому месту в папке → «Открыть окно PowerShell здесь».

### Шаг 3. Создать файл настроек `.env`

Файл `.env` хранит пароли и настройки. Его **не заливают в git** (он уже в .gitignore).

1. В папке проекта найдите файл **`.env.example`** (если не видите — включите показ скрытых файлов в проводнике).
2. Скопируйте его и переименуйте копию в **`.env`** (без .example).
3. Откройте `.env` в блокноте или в Cursor.

Должно быть примерно так:

```env
POSTGRES_PASSWORD=change_me_strong_password
SECRET_KEY=change_me_min_32_chars_change_me_min_32_chars
CORS_ORIGINS=https://example.com
DOMAIN=example.com
```

Замените значения на свои (для локального запуска можно так):

| Переменная | Что это | Пример для локального запуска |
|------------|---------|--------------------------------|
| **POSTGRES_PASSWORD** | Пароль к базе данных. Придумайте свой, не оставляйте «change_me». | `MySecureDbPass123` |
| **SECRET_KEY** | Секретный ключ для сессий и токенов. Должен быть **не короче 32 символов**, лучше случайный. | См. ниже, как сгенерировать. |
| **CORS_ORIGINS** | С какого адреса разрешён доступ к API. Для локального запуска — адрес, с которого открываете сайт. | `http://localhost` или `http://127.0.0.1` |
| **DOMAIN** | Домен, под которым будет открываться сайт. Локально — localhost. | `localhost` |

**Как сгенерировать SECRET_KEY (32+ символов):**

В PowerShell выполните один раз:

```powershell
[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }) -as [byte[]])
```

Скопируйте полученную строку и вставьте в `.env` как значение `SECRET_KEY=` (без кавычек).

Пример итогового `.env` для локального запуска:

```env
POSTGRES_PASSWORD=MySecureDbPass123
SECRET_KEY=ваша_длинная_случайная_строка_из_команды_выше
CORS_ORIGINS=http://localhost
DOMAIN=localhost
```

Сохраните файл.

### Шаг 4. Запустить деплой

В той же папке (где `docker-compose.yml` и `.env`) откройте PowerShell и выполните:

```powershell
docker compose up -d --build
```

Что происходит:

- `docker compose` — управление контейнерами по файлу `docker-compose.yml`;
- `up` — поднять все сервисы;
- `-d` — в фоне, чтобы окно не было занято;
- `--build` — перед запуском заново собрать образы (важно при первом запуске и после изменений кода).

Первый раз это может занять 3–10 минут: скачиваются образы, собираются backend и frontend. В конце должны появиться строки вроде:

```
[+] Running 4/4
 ✔ Container new_project-db-1       Started
 ✔ Container new_project-backend-1  Started
 ✔ Container new_project-web-1      Started
```

Ошибки бывают, если Docker не запущен или порты 80/443 заняты. См. раздел «Частые проблемы» внизу.

### Шаг 5. Проверить, что всё работает

1. Откройте браузер и перейдите по адресу: **http://localhost**
2. Должна открыться страница входа приложения.
3. API можно проверить так: **http://localhost/api/docs** — откроется документация Swagger.
4. Проверка здоровья API: **http://localhost/api/health** — должен вернуться ответ вроде `{"status":"ok"}`.

Если страница не открывается — смотрите логи (шаг 6).

### Шаг 6. Логи (если что-то не работает)

В PowerShell в папке проекта:

```powershell
docker compose logs -f --tail=100
```

Показаны последние 100 строк логов всех сервисов. Чтобы выйти — Ctrl+C.

Только backend:

```powershell
docker compose logs -f backend --tail=50
```

Только база:

```powershell
docker compose logs -f db --tail=30
```

По логам видно, упала ли миграция, не подключается ли backend к БД и т.д.

### Шаг 7. Остановить проект

Когда нужно выключить всё:

```powershell
docker compose down
```

Данные в базе сохраняются (они в томе `db_data`). При следующем `docker compose up -d --build` всё поднимется с теми же данными.

## Вариант 2: Деплой на сервере в интернете (VPS)

Чтобы сайт был доступен по адресу типа `https://ваш-домен.ru`, нужен сервер (VPS) и домен.

### Шаг 1. Арендовать VPS и домен

- **VPS**: любой провайдер (Timeweb, Selectel, Reg.ru, Beget, DigitalOcean, и т.п.). Достаточно 1 GB RAM, 1 CPU.
- **Домен**: купить домен и направить его на сервер:
  - В панели управления доменом создать **A-запись**: имя `@` (или ваш поддомен), значение — **IP вашего VPS**.

### Шаг 2. Подключиться к серверу по SSH

На Windows удобно через PowerShell:

```powershell
ssh root@ВАШ_IP_АДРЕС
```

Подставьте реальный IP. Пароль или ключ — как выдал провайдер при создании сервера.

### Шаг 3. Установить Docker на сервере (Ubuntu/Debian)

На сервере выполните по очереди:

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-plugin
sudo systemctl enable docker
sudo systemctl start docker
sudo usermod -aG docker $USER
```

Затем выйдите и зайдите снова по SSH (или выполните `newgrp docker`), чтобы права применились. Проверка:

```bash
docker --version
docker compose version
```

### Шаг 4. Загрузить проект на сервер

**Вариант А — через Git (если проект в репозитории):**

```bash
cd ~
git clone URL_ВАШЕГО_РЕПОЗИТОРИЯ learning-portal
cd learning-portal
```

**Вариант Б — через копирование папки (если без Git):**  
Скопируйте папку проекта на сервер (через WinSCP, FileZilla или `scp` с вашего компьютера).

### Шаг 5. Создать `.env` на сервере

На сервере в папке проекта:

```bash
cp .env.example .env
nano .env
```

Заполните так (подставьте свои значения):

| Переменная | Что подставить |
|------------|----------------|
| **POSTGRES_PASSWORD** | Надёжный пароль только для базы данных |
| **SECRET_KEY** | Длинная случайная строка (32+ символов), сгенерировать можно так: `openssl rand -base64 32` |
| **CORS_ORIGINS** | URL, с которого будут заходить пользователи: `https://ваш-домен.ru` (без слэша в конце) |
| **DOMAIN** | Ваш домен: `ваш-домен.ru` (без https://) |

Пример:

```env
POSTGRES_PASSWORD=ОченьНадёжныйПароль123!
SECRET_KEY=результат_команды_openssl_rand_base64_32
CORS_ORIGINS=https://ваш-домен.ru
DOMAIN=ваш-домен.ru
```

Сохраните в nano: Ctrl+O, Enter, Ctrl+X.

### Шаг 6. Запустить деплой на сервере

В папке проекта на сервере:

```bash
docker compose up -d --build
```

Дождитесь окончания сборки. Проверьте контейнеры:

```bash
docker compose ps
```

Все сервисы должны быть в состоянии «Up».

### Шаг 7. Проверить сайт и HTTPS

1. В браузере откройте **https://ваш-домен.ru**
2. Caddy при первом обращении сам получит сертификат Let's Encrypt для HTTPS.
3. API: **https://ваш-домен.ru/api/docs** и **https://ваш-домен.ru/api/health**

Если домен ещё не обновился (DNS), подождите 5–15 минут или проверьте A-запись.

### Шаг 8. Обновление (после изменений в коде)

На сервере в папке проекта:

```bash
git pull
docker compose up -d --build
```

Миграции БД выполняются автоматически при старте backend.

## Частые проблемы

### «Port 80 is already in use» / порт занят

На Windows порт 80 может занимать IIS или другое приложение. Варианты:

- Отключить службу, которая слушает 80 порт, или
- Временно изменить в `docker-compose.yml` у сервиса `web` порты, например: `"8080:80"` и открывать сайт как **http://localhost:8080**. Тогда в `.env` задайте `CORS_ORIGINS=http://localhost:8080` и `DOMAIN=localhost:8080` (или оставьте localhost, если Caddy так примет).

### Страница не открывается / 502 Bad Gateway

- Убедитесь, что все контейнеры запущены: `docker compose ps`.
- Посмотрите логи backend: `docker compose logs backend --tail=50`. Часто там видно ошибку подключения к БД или падение при старте (например, из-за миграций). Проверьте, что в `.env` правильный `POSTGRES_PASSWORD` и он совпадает с тем, что используется в `DATABASE_URL` внутри docker-compose (пароль подставляется из `POSTGRES_PASSWORD`).

### Ошибка CORS в браузере

В консоли браузера пишет про CORS. Нужно, чтобы **CORS_ORIGINS** в `.env` точно совпадал с тем адресом, с которого вы открываете сайт (включая http/https и порт). Например, если открываете `http://localhost:3000`, то и в `.env` должно быть `CORS_ORIGINS=http://localhost:3000`. После изменения перезапустите: `docker compose up -d --build`.

### Backend падает при старте (миграции, база)

- Проверьте логи: `docker compose logs backend`.
- Убедитесь, что контейнер `db` запущен и здоров: `docker compose ps`. Backend ждёт, пока БД станет готова, затем выполняет `alembic upgrade head`. Если в логах ошибка подключения к БД — проверьте `POSTGRES_PASSWORD` в `.env` (и что в `DATABASE_URL` используется тот же пароль).

### Как создать первого администратора

После первого запуска в базе нет пользователей. В проекте есть скрипт **`backend/create_admin_fixed.py`**: он создаёт пользователя с email **admin@example.com** и паролем **admin123** (роль — администратор).

**Если деплой через Docker:**

Выполните команду **в папке проекта** (где лежит `docker-compose.yml`):

```powershell
docker compose exec backend python create_admin_fixed.py
```

На Linux/Mac то же самое без `compose` в имени, если у вас новая версия: `docker compose exec backend python create_admin_fixed.py`.

После этого откройте сайт (http://localhost или https://ваш-домен.ru), нажмите «Войти» и введите:
- **Логин:** `admin@example.com`  
- **Пароль:** `admin123`

Рекомендуется сразу после первого входа сменить пароль (если в приложении есть смена пароля) или создать нового пользователя с другим паролем и не использовать admin123 в работе.

## Краткая шпаргалка команд

| Действие | Команда (в папке с docker-compose.yml) |
|----------|----------------------------------------|
| Запустить всё | `docker compose up -d --build` |
| Остановить | `docker compose down` |
| Логи всех сервисов | `docker compose logs -f --tail=100` |
| Логи backend | `docker compose logs -f backend` |
| Статус контейнеров | `docker compose ps` |
| Перезапустить только backend | `docker compose restart backend` |

После первого успешного деплоя для обновления кода достаточно: скопировать/подтянуть изменения, поправить `.env` при необходимости и снова выполнить `docker compose up -d --build`.
