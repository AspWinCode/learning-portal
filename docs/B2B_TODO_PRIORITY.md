# B2B: приоритет доработок по ТЗ

Рекомендуемый порядок: от быстрых и высокоэффективных к более тяжёлым.

---

## Приоритет 1 — быстрые победы (1–2 дня)

### 1.1 Кнопка «Поставить задачу найти контакты» при 0 контактов
**Где:** карточка школы (B2BSchoolsPage), секция «Контакты».  
**Что:** если `editingSchool.contacts?.length === 0`, показать кнопку «Поставить задачу найти контакты». По клику — вызов API создания задачи (или отдельный эндпоинт), задача назначается `editingSchool.manager_id`, заголовок вида «Найти контакты (директор/завуч): {школа}».

**Шаги:**
- Backend: добавить `POST /api/b2b-schools/{id}/task-find-contacts` (или переиспользовать общий создатель задач с `created_by`/`assigned_to` из контекста). Либо фронт вызывает общий API задач с `title` и `assigned_to_id = school.manager_id`.
- Frontend: в блоке контактов, если контактов 0, рендерить `<Button onClick={...}>Поставить задачу найти контакты</Button>`, по клику — создание задачи через API и toast/успех.

### 1.2 Кнопка «Запросить» для письма поддержки
**Где:** карточка школы, блок «Письмо поддержки».  
**Что:** кнопка «Запросить» → ставим статус «запрошено» и создаём задачу менеджеру школы (например «Запросить письмо поддержки: {школа}»).

**Шаги:**
- Backend: либо в `PATCH/PUT` школы при смене `support_letter_status` на `requested` создавать задачу (триггер), либо отдельный `POST /api/b2b-schools/{id}/request-support-letter`.
- Frontend: рядом с селектом статуса кнопка «Запросить» → обновить школу `support_letter_status: 'requested'` (и при необходимости вызвать создание задачи, если выбран отдельный эндпоинт).

### 1.3 Кнопки в шапке карточки
**Где:** шапка диалога карточки школы.  
**Что:** явные кнопки «+ Задача», «+ Взаимодействие», «+ Мероприятие», «Партнёрство», «Письмо поддержки». Партнёрство и Письмо поддержки — скролл к соответствующей секции в том же диалоге (или открыть секцию). Задача / Взаимодействие / Мероприятие — см. ниже (взаимодействия и мероприятия — отдельные фичи).

**Шаги:**
- Frontend: в `DialogTitle` или сразу под ним добавить `Stack direction="row"` с кнопками. «Партнёрство» и «Письмо поддержки» — `scrollIntoView` к секциям или табы внутри диалога. «+ Задача» — переход на `/tasks` с query или открытие модалки создания задачи (если есть общий API задач с `assigned_to_id`).

## Приоритет 2 — секция «Лиды» в карточке (≈1 день)

### 2.1 Блок «Лиды» в карточке школы + «Передать в обработку»
**Что:** в карточке школа — секция «Лиды»: список лидов с `b2b_school_id = school.id`, источник (мероприятие/источник лида). Кнопка «Передать в обработку» — смена статуса лидов или просто маркер «передано» (по ТЗ — действие менеджера).

**Шаги:**
- Backend: уже есть `Lead.b2b_school_id`. Добавить эндпоинт `GET /api/b2b-schools/{id}/leads` (или включить `leads` в ответ `GET /api/b2b-schools/{id}` через relationship/подзапрос), вернуть список лидов с полями id, source, status, created_at.
- Backend: при необходимости «Передать в обработку» — либо смена статуса лидов (например в «в работе»), либо отдельный флаг. Эндпоинт `POST /api/b2b-schools/{id}/leads/transfer` или PATCH лидов.
- Frontend: в карточке школа новая секция «Лиды»: запрос лидов по school_id, таблица или список; кнопка «Передать в обработку» → вызов API и обновление списка.

## Приоритет 3 — журнал взаимодействий (2–3 дня)

### 3.1 Модель и API взаимодействий
**Что:** сущность «взаимодействие» к школе: тип (звонок/письмо/встреча), дата, итог/комментарий, кто создал. При добавлении — опционально предложить «следующий шаг» и обновить next_step/next_step_date школы.

**Шаги:**
- Backend: миграция — таблица `b2b_school_interactions` (id, b2b_school_id, type: enum call/letter/meeting, happened_at, summary, created_by_id, created_at). Модель, схемы.
- Backend: `GET /api/b2b-schools/{id}/interactions`, `POST /api/b2b-schools/{id}/interactions` (body: type, happened_at, summary, next_step?, next_step_date?). При POST при необходимости обновлять school.next_step/next_step_date.
- Frontend: в карточке школа секция «Взаимодействия»: список по дате, форма «Добавить» (тип, дата, итог, след. действие + дата). После добавления — обновить данные школы в диалоге.

## Приоритет 4 — мероприятия с форматом и авто-задачами (2–4 дня)

### 4.1 Модель мероприятия и «Добавить мероприятие»
**Что:** не только даты на школе, а сущность «мероприятие B2B»: школа, формат (офлайн/онлайн/гибрид), тип для онлайн (вебинар/олимпиада/день открытых дверей), даты. При создании онлайн-мероприятия — создавать задачи: отправить ссылку, рассылка по чатам, напоминания за 2 и 1 день, после — занести лиды.

**Шаги:**
- Backend: миграция — таблица `b2b_school_events` (id, b2b_school_id, format: offline/online/hybrid, online_type: nullable webinar/olympiad/open_doors, event_dates JSON, created_at). Либо хранить в JSON на школе (event_dates уже есть; добавить поле events: JSON с массивом { format, online_type, dates }).
- Backend: `POST /api/b2b-schools/{id}/events` (body: format, online_type?, dates[]). При format=online создавать задачи через существующий `_create_b2b_task` (напоминания за 2 и 1 день, «отправить ссылку», «рассылка по чатам», «занести лиды» с due по дате мероприятия).
- Frontend: в карточке кнопка «Добавить мероприятие» → диалог: формат (офлайн/онлайн/гибрид), если онлайн — тип, даты. Отправка POST, обновление списка мероприятий/дат на школе.

### 4.2 Связь лидов с мероприятием
**Что:** при «занести лиды» лиды привязываются к школе и к мероприятию (если есть). В блоке «Лиды» показывать источник — мероприятие.

**Шаги:**
- Lead уже имеет b2b_school_id. Опционально добавить `b2b_event_id` (FK на b2b_school_events) или хранить в source/comment. Затем в GET лидов по школе возвращать источник (мероприятие/тип).

## Приоритет 5 — партнёрство: авто-задачи по чек-листу (1–2 дня)

### 5.1 Триггеры при изменении чек-листа партнёрства
**Что:** при отметке пункта партнёрства (например «подписано школой») система создаёт следующую задачу (например «получить подпись с нашей стороны»).

**Шаги:**
- Backend: при `PUT /api/b2b-schools/{id}` с изменённым `partnership` (сравнить старый/новый) вызывать хелпер `_on_b2b_partnership_updated(school, previous_partnership, current_user_id)`. По ключам чек-листа (invited → agreement_sent → signed_school → signed_both → originals_received → icon_on_site → active_partner) определять «следующий шаг» и создавать одну задачу менеджеру.
- Frontend: без изменений (чек-лист уже сохраняется); достаточно бэкенд-логики.

## Приоритет 6 — мелкие улучшения (по желанию)

- **Риски:** «нет контактов 48ч» — заменить или дополнить текущий «найти контакты >3 дн» на отдельный срез «без контактов 48ч» (школы в find_contacts, созданы/обновлены более 48ч назад). «Проведено без лидов 24–48ч» — фильтр по event_done/walkthrough_done и дате проведения + нет лидов.
- **Метка онлайн/офлайн в канбане:** добавить на школу поле `preference: online | offline | any`, в карточке канбана показывать маленький Chip/иконку.
- **«Закрыть» в Плане:** если пункт плана — это задача (Task), кнопка «Закрыть» → PATCH задачи status=done или удаление. Нужна связь «пункт плана» ↔ задача (сейчас план строится по next_step_date школ, не по задачам). Либо «Закрыть» = очистить next_step и поставить следующую дату (перенести выполненное).
