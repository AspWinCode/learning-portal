# Owner workspace — дорожная карта и сверка с ТЗ

Модуль: **`/owner-workspace`**, API **`/api/owner-workspace/...`**: **admin / owner** — полный доступ; **sales / trainer** — только проекты (владелец или участник + подпроекты), контакты и задачи по правилам видимости (см. `owner_workspace_access.py`).

---

## Сделано (покрытие ТЗ)

| Область | Что есть |
|---------|----------|
| **Задачи** | Список, канбан, календарь; поиск, фильтры (проект, контакт, статус, приоритет, исполнитель, просрочка, активные), **сортировка**, массовые действия |
| **Карточка задачи** | Редактирование, проект/контакт/исполнитель, дедлайн, `start_at`, теги, чек-лист, вложения (JSON), **комментарии**, **история**, связь с сообщениями, **предыдущая → следующая** |
| **Завершение** | Модалка: «просто закрыть» / «закрыть и создать следующую» |
| **Проекты** | Список, фильтры (статус, поиск, ответственный, просрочка по проекту), карточка: **название/описание/статус**, ответственный, участники, подпроект, контакты **с удалением из проекта**, задачи, **статистика** (всего / активные / завершённые / просроченные), **архив с предупреждениями** |
| **Контакты** | Список, фильтры, **редактирование карточки**, привязка к проекту, **снятие с проекта из карточки контакта** (по каждому проекту), задачи **с секциями активные / завершённые·отменённые**, переписка, **поиск по сообщениям** в карточке |
| **Коммуникации** | **3 колонки** (диалоги + поиск, переписка + поиск по сообщениям, контекст контакта), MAX sync, задача из сообщения, привязка к задаче |
| **Поиск** | Единый поиск по задачам, проектам, контактам, сообщениям |
| **Digest** | Сводка по дедлайнам |
| **Уведомления** | In-app: колокольчик, прочитано; **дедлайн скоро / просрочка**, **назначение исполнителя**, **комментарий** (исполнитель и автор задачи); вкладка и маршрут **`/owner-workspace/notifications`** |
| **Аудит** | Вкладка «История» + история в задаче |
| **Селекты** | Полные каталоги проектов/контактов независимо от фильтров списков |
| **Настройки** | Вкладка и маршрут **`/owner-workspace/settings`**: вид задач, размер страницы списка, окно сводки по дедлайнам, область сводки — **хранение в БД** (`GET/PATCH /me/preferences`) |

## Частично / отличия от формулировок ТЗ

- **URL / меню (ТЗ §6, §16):** один экран с вкладками; **deep-link** query `?tab=<slug>&task=<id>` (слаги включают `settings`, `history`); отдельные маршруты **`/owner-workspace/notifications`**, **`/owner-workspace/settings`**; нет отдельных `/tasks`, `/projects` под задачник.
- **Роли (§4):** sales/trainer подключены к API и фильтрации; отдельные «роли внутри проекта» (руководитель/менеджер) не заведены — грубее: владелец проекта / участник / полный доступ.
- **Уведомления (§7.5):** есть **назначение** и **комментарий** + дедлайны; **нет** email/push и прочих типов из ТЗ; отдельный раздел — **внутри owner-workspace** (вкладка + прямой URL).
- **Настройки (§7.6):** есть **UI задачника** (персональные умолчания UI); глобальные/системные настройки модуля в ТЗ не детализированы.
- **Карточка проекта (§7.2.2):** блоки в одном диалоге, без вкладок; **нет дерева подпроектов и переноса подпроекта**.
- **Список проектов:** нет явного **имени ответственного** в карточке (фильтр по ответственному есть).
- **Список контактов:** в сетке нет **компании, тегов, даты последнего взаимодействия**.
- **Задачи по контакту:** ~~нет раздельных секций~~ — **сделано:** активные vs завершённые/отменённые.
- **Коммуникации (§7.4):** ~~нет 3 колонок и поиска по диалогам~~ — **сделано:** 3 колонки, поиск по списку диалогов и по ленте; **непрочитанные** в API пока заглушка (`unread_count=0`).
- **Задача:** удаление — `DELETE /tasks/{id}` (только admin/owner); «архив» = статус **Отменена**; у **завершённых/отменённых** нельзя менять поля кроме **статуса** (или полное сохранение при возврате в активный статус).
- **Производительность (§14.1):** пагинация `GET /tasks` (`limit`/`offset`, ответ `items`+`total`) и **TablePagination** в режиме «Список»; канбан/календарь — до 500 задач за запрос с предупреждением при превышении.
- **Аналитика (§17):** без отдельных отчётов по скорости закрытия и т.д.

Бывает рассинхрон: в `alembic_version` уже **0083**, а объекты из более ранних ревизий (например **0079** — `sms_messages.scheduled_at`, таблица `max_messages`) в БД отсутствуют.

**Проверка:** список колонок тем же подключением, что у приложения:

`docker compose exec backend python -c "… information_schema …"`

**Исправление:** догнать схему SQL вручную или откат/накат миграций (осторожно на проде). После правок — `docker compose restart backend` и свежие логи.

## История закрытых этапов в коде

- Этап «контакты в проекте»: API `DELETE …/projects/{id}/contacts/{contactId}`, UI в **проекте** и в **контакте**.
- Архив проекта с предупреждениями; карточка проекта (редактирование + счётчики задач в API).
- Уведомления по дедлайнам (таблица + сервис refresh); сортировка задач; каталоги для селектов.
- Пагинация списка задач: API `OwnerWorkspaceTaskListResponse`, UI `TablePagination` в вкладке «Задачи» (режим список).
- Удаление задачи (`DELETE`), блокировка полей карточки для completed/cancelled; отмена = статус в UI.
- Уведомления: `task_assigned`, `task_comment`; дедуп-ключи; UI вкладка «Уведомления», пункт меню и deep-link на `/owner-workspace/notifications`.
- Deep-link: `/owner-workspace?tab=…&task=…`, переход с `/notifications` на другие вкладки через `/owner-workspace?…`, в адресе появляется `task=` при открытой карточке.
- Карточка контакта: две секции задач + фильтр переписки; коммуникации: диалоги / тред / контекст с кнопкой «Открыть карточку».
- Настройки задачника: таблица `owner_workspace_user_preferences`, API `GET/PATCH /api/owner-workspace/me/preferences`, вкладка + `/owner-workspace/settings`.
