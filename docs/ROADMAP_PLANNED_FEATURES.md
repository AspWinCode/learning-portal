## 1. Гибкая ролевая модель (Custom Roles)

### Проблема
Сейчас роли зашиты в коде: `owner | admin | sales | trainer | parent | guest`.
Нельзя создать роль «инвестор», «ассистент тренера», «менеджер по качеству» и т.д.

### Что нужно сделать

**Owner** получает интерфейс управления ролями, в котором можно:

- Создавать именованную роль (произвольное название)
- Выбирать набор разрешений из списка (чекбоксы по модулям/действиям)
- Создавать аккаунты пользователей под любую роль
- Изменять/архивировать роль

**Примеры ролей, которые должны стать создаваемыми:**

| Название | Примерный набор прав |
|----------|----------------------|
| Sales-менеджер | Лиды, задачи, инвойсы |
| Менеджер по работе с клиентами | Чат с родителями, оплаты |
| Инвестор | Только просмотр финансовых дашбордов |
| Ассистент тренера | Просмотр группы, оценки |
| HR | Управление тренерами |

**Текущая роль `sales`** — стать встроенным шаблоном роли или удалить как хардкодную сущность.

### Технические изменения (к проработке)

- Новая таблица `roles` (id, name, description, permissions: JSON)
- Новая таблица `role_permissions` или хранить как jsonb-поле
- В `User` заменить enum-поле `role` на FK → `roles.id`
- Миграция существующих пользователей на новые записи ролей
- Frontend: новая страница Owner → Управление ролями (CRUD)
- Backend: рефакторинг всех `Depends(require_sales_admin_owner)` → проверка конкретных permissions

### Приоритет
Высокий. Влияет на всю архитектуру авторизации.

## 2. Внешнее хранилище документов (Synology NAS)

### Что нужно

Возможность сохранять документы из системы на внешний диск Synology:

- Загруженные файлы (вложения в задачи, карточки лидов, характеристики)
- Экспортированные отчёты (Excel, PDF)
- Медиафайлы из мессенджера (см. раздел 4)

### Варианты интеграции (к проработке)

1. **Synology NAS как S3-compatible storage (MinIO-протокол)**
   - Synology DSM поддерживает S3-compatible API через пакет C2 Object Storage или через собственный MinIO
   - В backend использовать `boto3` / `aiobotocore` с endpoint → Synology
   - Единый интерфейс для всех объектов (медиа, документы)

2. **SMB/NFS mount в Docker-контейнере**
   - Монтировать сетевой диск как volume
   - Проще, но менее гибко

3. **Synology WebDAV**
   - Загрузка через WebDAV API
   - Подходит для документов, но не для медиа-стриминга

### Что нужно сделать
- Выбрать подход (рекомендуется вариант 1 — S3-compatible)
- Настроить Synology как object storage
- Добавить в backend сервис `StorageService` (абстракция над S3/MinIO)
- Добавить env-переменные: `STORAGE_ENDPOINT`, `STORAGE_BUCKET`, `STORAGE_ACCESS_KEY`, `STORAGE_SECRET_KEY`
- Перевести загрузку файлов в системе на этот сервис

### Приоритет
Средний. Критично для мессенджера (медиафайлы).

## 3. Редизайн UI/UX

### Текущие проблемы (выявлены при анализе)

- 66 страниц при 9 shared-компонентах → дублирование таблиц, фильтров, модалок
- Нет скелетонов загрузки (только CircularProgress)
- Нет breadcrumbs для вложенной навигации
- RichTextEditor на contentEditable без нормальной библиотеки
- Нет оптимистичных обновлений UI
- Навигация через query params без стандарта

### Что нужно проработать

**Компоненты (extract & унифицировать):**
- `DataTable` — универсальная таблица с сортировкой, фильтром, пагинацией
- `FilterPanel` — панель фильтров с сохранением состояния в URL
- `FormDialog` — универсальный диалог с формой
- `ConfirmDialog` — диалог подтверждения действия
- `StatusChip` — чип статуса с маппингом цвет/иконка
- `LoadingSkeleton` — скелетон под разные типы контента
- `EmptyState` — пустое состояние списков

**UX улучшения:**
- Добавить breadcrumbs на страницах с вложенной навигацией
- Заменить RichTextEditor на Tiptap или Slate
- Добавить react-hook-form + zod для форм
- Добавить React Query для кэширования и оптимистичных обновлений
- Стандартизировать query params навигацию

**Дизайн:**
- Пересмотреть цветовую схему и типографику
- Добавить dark mode (опционально)
- Улучшить мобильную адаптацию сложных страниц (таблицы → карточки на xs)

### Приоритет
Средний. Можно делать итерационно по страницам.

## 4. Модуль мессенджера

> Полное ТЗ на мессенджер — см. файл `MESSENGER_TZ.md` в этой же папке.

### Краткое резюме

Встроенный коммуникационный модуль (не отдельный продукт), глубоко интегрированный с CRM/ERP-логикой портала.

**Ключевые сценарии:**
- Групповые чаты учебных групп
- Чат родителя со службой заботы
- Системные напоминания о занятиях
- Кнопка «Оплатить» в чате
- Push-уведомления (web + Android + iOS)
- Рассылки и опросы

**Новые технологии в стек:**
- Redis (pub/sub, presence, unread counts)
- WebSocket (realtime доставка)
- MinIO / Synology S3 (медиафайлы)
- Celery/Dramatiq (рассылки, обработка медиа)
- React Native (мобильное приложение)

**Этапность:**
1. Базовый мессенджер (группы, родительский чат, push, оплата)
2. Коммуникации (рассылки, опросы, шаблоны, модерация)
3. Масштабирование (Redis pub/sub, очереди, аналитика)
