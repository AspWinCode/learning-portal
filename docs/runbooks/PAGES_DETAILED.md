# Детальное описание страниц портала обучения

Документ описывает каждую страницу приложения: назначение, элементы интерфейса, действия пользователя и доступ по ролям.

---

## 1. Публичные страницы (без входа)

### 1.1. `/login` — Вход в систему (LoginPage)

**Назначение:** Авторизация по email и паролю, вход как гость, восстановление пароля.

**Элементы:**
- Заголовок «Вход в систему».
- Поле **Email** (обязательное).
- Поле **Пароль** (обязательное).
- Кнопка **«Войти»** — отправка формы, при успехе редирект на `/` (далее по роли).
- Кнопка **«Войти как гость»** — вызов `loginAsGuest()`, редирект на `/programs`.
- Ссылка **«Забыли пароль?»** — открывает диалог восстановления.

**Диалог «Восстановление пароля»:**
- Информация: код приходит в Telegram, если он привязан к аккаунту.
- **Шаг 1:** поле Email, кнопка «Получить код».
- **Шаг 2:** Email, код, новый пароль; кнопка «Сменить пароль».
- Ошибки и успешные сообщения отображаются в диалоге.

**Ошибки:** выводятся в `Alert` над формой (неверный логин/пароль, ошибка сети и т.д.).

---

### 1.2. `/set-password` — Установка пароля (SetPasswordPage)

**Назначение:** Установка пароля по ссылке приглашения (например, для родителя). Токен передаётся в query: `?token=...`.

**Элементы:**
- Текст про приглашение в кабинет родителя.
- Поле **«Новый пароль»** (минимум 6 символов).
- Поле **«Повторите пароль»**.
- Кнопка **«Установить пароль»**.
- Ссылка «На страницу входа».

**Поведение:**
- Без токена показывается сообщение об недействительной ссылке и кнопка на `/login`.
- После успешной установки — сообщение «Пароль установлен» и через 2 секунды редирект на `/login`.

---

### 1.3. `/anketa/specialist` — Анкета специалиста (SpecialistQuestionnairePage)

**Назначение:** Публичная форма для подачи заявки по программе «Специалист» (родитель/ребёнок, контакты, город и т.д.).

**Блоки полей:**
- **Родитель:** ФИО, телефоны, Telegram, email.
- **Обучающийся:** ФИО, дата рождения, телефон, Telegram, пол, город, школа, класс.
- **Контакты:** email ученика, предпочитаемый мессенджер, комментарий, источник.

**Обязательные:** ФИО родителя, телефон родителя, ФИО ребёнка, город.

**Действия:** Кнопка отправки анкеты. При успехе — экран «Спасибо! Анкета отправлена, менеджер свяжется».

## 2. Главная и дашборды

### 2.1. `/` — Редирект по роли (DefaultRedirect)

**Назначение:** После входа пользователь перенаправляется:
- **guest** → `/programs`
- **parent** → `/parent-dashboard`
- **sales** → `/tasks`
- **admin, trainer, owner** → `/dashboard`

---

### 2.2. `/dashboard` — Главная (DashboardPage)

**Роли:** admin, trainer, parent, owner.

**Содержимое:**
- Приветствие: «Добро пожаловать, {ФИО}!»
- Отображение текущей роли (Администратор / Владелец / Тренер / Родитель / Sales / Гость).

**Для роли owner — вкладки:**
1. **Главная** — краткая сводка и подсказка перейти к отчётности или финансовой модели.
2. **Отчётность по характеристикам** — встроенный контент с `ReportsPageContent` (контроль характеристик, отчёты по ученикам/тренерам, журнал, экспорт).
3. **Финансовая модель** — встроенный контент `FinancialModelContent`.
4. **Операционные отчёты** — вкладка `OperationalReportsTab`.

**Для не-owner:** блок «Быстрый доступ» с текстом про навигацию по меню.

---

### 2.3. `/parent-dashboard` — Дашборд родителя (ParentDashboardPage)

**Роли:** parent.

**Назначение:** Сводка по детям: прогресс по программе, оценки, характеристики, аналитика.

**Структура:** Для каждого ребёнка (из списка учеников родителя) выводится карточка.

**В каждой карточке:**
- ФИО ученика.
- Название и версия программы (если назначена).
- **Прогресс:** процент прохождения, прогресс-бар, «Оценено тем: X из Y».
- **Сравнение характеристик** (аккордеон): таблица полей текущей/предыдущей/позапрошлой характеристики; рейтинговые метрики (`*_rating`).
- **Динамика оценок** (если есть данные): график по месяцам (recharts LineChart).
- **Опубликованные характеристики:** выбор диапазона (начальная — конечная), отображение полей и значений.

Данные подгружаются: программы, ученики, прогресс по программам, сравнение характеристик, опубликованные характеристики, динамика оценок (API отчётов).

## 3. Ученики, группы, уроки

### 3.1. `/students` — Ученики (StudentsPage)

**Роли:** admin, trainer, owner, sales.

**Вкладки (через `?tab=`):**
- **students** — список учеников (по умолчанию).
- **ankety** — анкеты (студенческие карточки): черновики, заполненные, конвертированные, отменённые.
- **parents** — родители (список/управление).
- **trainers** — тренеры (для создания/редактирования, если доступно).

**Вкладка «Ученики»:**
- Поиск по имени.
- Фильтры: статус (все / активные / архивные), тип (грант / индивидуальный / платный), группа, тренер, программа.
- Быстрые фильтры: «Без группы», «Из лида» (если есть права).
- Таблица: ФИО, родитель, группа, тренер, программа, абонемент, дата начала, статус и т.д.
- Действия: добавить ученика, редактировать, открыть детали (popup), меню по строке (архив, счета и т.д.).
- Для owner/sales/admin: создание ученика с привязкой к существующему или новому родителю; опция «Создать анкету» (карточку) вместе с учеником.

**Вкладка «Анкеты»:**
- Фильтр по статусу анкеты: все / новая / заполнена / конвертирована / отменена.
- Список карточек (student cards): можно открыть форму редактирования (drawer), конвертировать в ученика (с разрешением конфликтов: существующий родитель/ученик или новый).
- Поддержка `?cardId=...` — открытие анкеты по ID.

**Дополнительно:**
- Диалоги: создание/редактирование ученика, создание родителя, счета ученика (пополнение/списание, шаблоны счетов), транзакции по счёту.
- Popup деталей ученика (`StudentDetailPopup`) по `?detail=id`.
- Для тренера: ограниченный набор полей и действий по правам.

---

### 3.2. `/groups` — Группы (GroupsPage)

**Роли:** admin, trainer, owner.

**Вкладки:** Активные / Архив.

**Список групп:**
- Таблица: название, тренер, направление, слоты (день, время), количество учеников, статус.
- Кнопки: создать группу, редактировать, состав.

**Создание/редактирование группы:**
- Название, тренер, направление (Первый шаг, Специалист, Эксперт, Backend, Frontend, ОГЭ, ЕГЭ и т.д.).
- Единиц за занятие, доп. ставка за единицу (опционально), дата начала.
- Формат урока: группой / индивидуально.
- Расписание: список слотов (день недели, начало, конец); добавление/удаление слотов.

**Диалог «Состав»:**
- Список учеников группы.
- Добавление ученика из выпадающего списка (активные ученики без группы или с правом перевода).

Тренер видит только свои группы, с полными данными по составу для отображения.

---

### 3.3. `/lessons` — Уроки (TrainerLessonsPage)

**Роли:** admin, trainer, owner, sales.

**Назначение:** Расписание занятий на выбранную дату, отметка посещаемости, управление слотами и кастомными уроками.

**Верхняя панель:**
- Выбор даты (назад/вперёд/сегодня).
- Кнопка добавления занятия: для админа/owner/sales — выбор «По расписанию группы» или «Ручной урок» (отработка / доп. платное / пробное).

**Слоты по расписанию группы:**
- Карточки по времени: группа, тренер, время, список учеников.
- Для каждого ученика: отметка «Был/Не был» и причина отсутствия (болел, олимпиада, мероприятие, другое), опционально комментарий.
- Кнопка «Сохранить посещаемость».
- Доп. действия (по правам): перенос занятия на другую дату, отмена, смена тренера, добавить ученика в урок, убрать ученика.

**Создание слота по группе:**
- Выбор группы, дата, время начала/окончания.

**Ручные (кастомные) уроки:**
- Отображаются отдельно за выбранный период.
- Создание: название, дата, время, тренер, тип (отработка / доп. платное / пробное), комментарий, выбор учеников; для отработки — привязка к конкретному пропуску.
- Отметка посещаемости по кастомным урокам так же сохраняется.

**Поведение:** Поддержка `?date=YYYY-MM-DD` и авто-открытия диалога по параметрам из других разделов (например, из пропусков).

## 4. Программы, оценки, характеристики

### 4.1. `/programs` — Программы (ProgramsPage / GuestProgramsPage)

**Роли:** admin, trainer, parent, guest.

**Для гостя (GuestProgramsPage):**
- Только просмотр: список программ (последние версии по каждой программе), поиск по названию.
- Выбор программы из списка — справа отображается структура: модули и темы (название, описание, результат). Редактирование недоступно.

**Для остальных ролей (ProgramsPage):**
- Дерево программ: группировка по «семьям» версий (одна базовая программа — несколько версий).
- Для каждой программы: аккордеон с версиями; внутри версии — модули и темы (название, описание, итоговый результат).
- Создание программы: название, модули (название + темы с полями темы).
- Создание новой версии на основе выбранной: копирование структуры, редактирование модулей/тем.
- Редактирование названия программы.
- Удаление (с учётом ограничений backend).

---

### 4.2. `/grades` — Оценки (GradesPage)

**Роли:** admin, trainer, parent.

**Назначение:** Выставление и просмотр оценок по темам программ.

**Блок «Выставить оценку» (для тренера/админа):**
- Выбор ученика (для родителя — только свои дети).
- После выбора подгружаются доступные темы (активные, ещё не оцененные по этой программе).
- Выбор темы, оценка (число), дата, комментарий — отправка.

**Блок «История оценок»:**
- Выбор ученика (и при необходимости программы).
- Таблица/список оценок по модулям и темам с датой и комментарием.
- Цветовая индикация оценки (например, зелёный ≥4.5, жёлтый/оранжевый/красный ниже).

**Родитель:** видит только своих детей и историю; выставление недоступно.

---

### 4.3. `/characteristics` — Характеристики (CharacteristicsPage)

**Роли:** admin, trainer, parent.

**Назначение:** Создание и согласование характеристик учеников (по шаблонам с полями, в т.ч. рейтинговыми).

**Шаблоны (admin):**
- Список шаблонов, создание нового (название), редактирование полей (название, тип, порядок).

**Характеристики:**
- Список с фильтрами (ученик, программа, месяц/год, статус).
- Статусы: черновик, на согласовании, опубликована, на доработку.
- Создание: выбор ученика, месяц/год, шаблон; заполнение полей шаблона (текст, рейтинги и т.д.). Для тренера подтягиваются программы ученика и темы для указания курса/модуля-темы.
- Редактирование черновика или отклонённой.
- Отправка на согласование (тренер).
- Согласование/отклонение (админ): кнопки «Одобрить» / «Отклонить», комментарий при отклонении.
- Просмотр: отображение полей и значений, опция «сырой» вид (JSON).

**Родитель:** просмотр опубликованных характеристик своих детей.

## 5. Отчёты

### 5.1. `/reports` — Отчётность (ReportsPage)

**Роли:** admin, owner.

**Назначение:** Сводные отчёты и экспорт данных.

**Вкладки:**
1. **Ученики** — таблица: ID, ФИО, статус; пагинация «Загрузить ещё».
2. **Тренеры** — таблица: тренер, кол-во групп, кол-во оценок, средняя оценка; чекбокс «Показывать архивных».
3. **Контроль характеристик** — выбор месяца и года; таблица по тренерам/ученикам: сдача характеристики в срок (1–6 число) — зелёный/красный индикатор.
4. **Журнал действий** — лог действий пользователей с пагинацией.
5. **Экспорт** — выбор учеников, тренеров, период (даты), формат (XLSX/CSV); кнопка «Скачать» — файл отчёта по оценкам.

## 6. Sales (продажи и CRM)

### 6.1. `/sales/dashboard` — Панель продаж (SalesDashboardPage)

**Роли:** admin, owner.

**Содержимое:**
- Кнопки быстрых действий: «Позвать снова на мероприятие» (→ `/sales/reinvite-event`), «Решили сразу» (→ `/sales/agreed`).
- Блоки по данным API `getSalesDashboard()`:
  - Задачи на сегодня/просроченные (списки с кнопками «написать», «позвонить», «карточка» → лид).
  - Регистрации на мероприятия (переход в «В мероприятия»).
- KPI/сводки при наличии в ответе API.

---

### 6.2. `/sales/leads` и `/sales/pipeline` — Лиды и воронка (SalesLeadsPage)

**Роли:** admin, owner, sales.

**Один компонент для двух маршрутов:** на pipeline отображается вид «Воронка», на leads — таблица лидов.

**Лиды (таблица):**
- Фильтры: статус, поиск, источник, тег, «только просроченные», город, школа (для воронки — школа).
- Режим отображения: таблица / канбан по статусам.
- Таблица: контакты, телефон, статус, источник, задачи, даты и т.д. Сортировка по столбцам.
- Действия: создать лида, открыть карточку (popup/drawer), задачи по лиду, счета, коммуникации, результат контакта (созвон), регистрация на мероприятие, конвертация в ученика, пометить «Отказ» (с указанием причины).

**Воронка (pipeline):**
- Колонки по этапам (новый, думают, недозвон, отказ, пробное, записан на мероприятие, решил сразу и т.д.).
- Карточки лидов в колонках; фильтр по школе.
- Перетаскивание между колонками (смена статуса) при поддержке в UI.

**Карточка лида:**
- Контактные данные, статус, задачи (создать/закрыть задачу), счета, история коммуникаций, отправка информации (шаблон + канал), запись на событие, конвертация.

---

### 6.3. `/sales/events` — События (SalesEventsHubPage → вкладка «События»)

**Роли:** admin, owner, sales.

**SalesEventsHubPage** — общая оболочка с вкладками:
- События
- Дожать на обучение (post-visit)
- Повторно позвать (reinvite)
- Решили сразу (agreed)
- Счета (invoices)

**Вкладка «События» (SalesEventsPageContent):**
- Список мероприятий (мастер-классы и т.п.): название, дата/время, локация, вместимость.
- Создание мероприятия: название, описание, начало/конец, локация, вместимость.
- Выбор события → список регистраций (лиды, записанные на событие).
- Регистрация лида на событие: выбор лида, заметка.
- Массовые действия по регистрациям (например, отметка пришедших).

---

### 6.4. `/sales/post-visit` — Дожать на обучение (SalesPostVisitPage)

**Доступ:** через хаб `/sales/events`, вкладка «Дожать на обучение».

**Назначение:** Работа с лидами после посещения мероприятия: список, фильтры, действия по переводу в ученики или следующие шаги.

---

### 6.5. `/sales/reinvite-event` — Повторно позвать (SalesReinviteEventPage)

**Доступ:** через хаб или кнопку с дашборда продаж.

**Назначение:** Выбор лидов с тегом «пригласить на следующее мероприятие» (или по правилу), выбор события и массовая отправка приглашений/напоминаний.

---

### 6.6. `/sales/agreed` — Решили сразу (SalesAgreedPage)

**Назначение:** Лиды в статусе «решил сразу»: список, конвертация в ученика, создание счёта и т.д.

---

### 6.7. `/sales/invoices` — Счета (SalesInvoicesPage)

**Роли:** sales (отдельный маршрут), также вкладка в хабе событий.

**Назначение:** Создание и отправка счетов лидам, список счетов, отправка по email.

---

### 6.8. `/sales/instructions` — Инструкции для продаж (SalesInstructionsPage)

**Роли:** admin, owner, sales (просмотр); редактирование — admin, owner.

**Содержимое:**
- Список инструкций (карточки): заголовок, превью текста.
- Редактирование/создание: заголовок, тело (RichTextEditor с HTML, вставка изображений до ~400 KB).
- Удаление с подтверждением.

---

### 6.9. `/sales/absences` — Пропуски (SalesAbsencesPage)

**Роли:** admin, owner, sales.

**Назначение:** Учёт пропусков занятий и назначение отработок.

**Фильтр:** по этапу (нужна отработка / отработка назначена / отработал / пропустил отработку).

**Список:**
- Ученик, дата урока, группа, причина отсутствия (был/не был, болел, олимпиада и т.д.), этап.
- Действия: сменить этап, «Подобрать отработку» — открывается диалог с вариантами слотов на ближайшие 3 недели; назначение выбранного слота или переход в ручное создание урока (`/sales/manual-lessons?create=1&absence_id=...&student_id=...`).

---

### 6.10. `/sales/debts` — Оплаты / задолженности (SalesDebtsPage)

**Роли:** admin, owner, sales.

**Вкладки:**
1. **Все** / **Просрочено** / **Скоро** — статусы оплат по ученикам (next_payment_date и т.д.): таблица учеников с датами и статусами.
2. **Операции банка** (только owner/admin, не sales): список банковских операций (импорт из Точка Банк), сопоставление с учеником/счётом, разнесение по статьям и «куда». Ручной импорт выписки, кнопка «Импорт Точка» для подтягивания операций.

**Действия:** Применить операцию к ученику (поиск ученика, привязка), массовый импорт из файла.

### 6.11. `/sales/program-makeup` — Совместимость программ для отработок (SalesProgramMakeupPage)

**Роли:** admin, owner.

**Интерфейс:** Таблица пар (программа ученика → программа отработки). Добавление пары: выбор двух программ из выпадающих списков. Удаление строки.

### 6.12. `/sales/tax-deduction` — Справка налогового вычета (SalesTaxDeductionPage)

**Роли:** admin, owner, sales.

**Назначение:** Формирование PDF-справки для налогового вычета (КНД 1151158).

**Поля формы:**
- Организация: ИНН, КПП, наименование, номер/корректировка справки, год, очная форма обучения.
- Налогоплательщик: ФИО, ИНН, дата рождения, документ (код типа, серия/номер, дата выдачи).
- Сумма расходов; признак «Налогоплательщик и обучаемый одно лицо» (да/нет).
- Если не одно лицо — блок с данными обучаемого (ФИО, ИНН, документ и т.д.).
- Подпись: ФИО подтверждающего, дата, кол-во листов.

**Действие:** Кнопка «Сформировать» — скачивание PDF `spravka_KND_1151158.pdf`.

## 9. Задачи и проекты

### 9.1. `/tasks` — Задачи (TasksPage)

**Роли:** admin, owner, sales.

**Назначение:** Единый список задач (школьные, по лидам, по оплатам, отработкам и т.д.) и «план на сегодня».

**Структура (зависит от роли):**
- Вкладки/фильтры по категориям (schools, makeups, payments и т.д.) и по статусу (активные/архивные).

## 11. Общие компоненты

- **Layout:** Боковое меню (пункты по роли), шапка с логотипом, поиском (глобальный поиск для sales с счётчиком алертов), меню пользователя (профиль, Telegram, пароль, логотип школы, выход). Контент страницы рендерится внутри Layout.
- **PrivateRoute:** Проверка авторизации и роли; при несовпадении роли — экран 403; при отсутствии токена — редирект на `/login`.

Этот файл можно использовать как справочник по страницам и их функционалу при доработках и онбординге.
