# Owner workspace — дорожная карта и сверка с ТЗ

Модуль: **`/owner-workspace`**, API **`/api/owner-workspace/...`**: **admin / owner** — полный доступ; **sales / trainer** — только проекты (владелец или участник + подпроекты), контакты и задачи по правилам видимости (см. `owner_workspace_access.py`).

---

## Сделано (покрытие ТЗ)

| Область | Что есть |
|---------|----------|
| **Задачи** | Список, канбан, календарь; поиск, фильтры (проект, контакт, статус, приоритет, исполнитель, просрочка, активные), **сортировка**, **чипы-счётчики по статусам** (`GET /tasks/status-counts` + клик = фильтр), **краткая аналитика** (`GET /analytics/tasks-overview`), массовые действия |
| **Карточка задачи** | Редактирование, проект/контакт/исполнитель, дедлайн, `start_at`, теги, чек-лист, вложения (JSON), **комментарии**, **история**, связь с сообщениями, **предыдущая → следующая** |
| **Завершение** | Модалка: «просто закрыть» / «закрыть и создать следующую» |
| **Проекты** | Список (**в т.ч. дата обновления**, ответственный, счётчики), фильтры (статус, поиск, ответственный, просрочка по проекту), карточка: **название/описание/статус**, ответственный, **участники с ролями** (`member` / `manager` в БД, менеджер ведёт состав), дерево подпроектов и перенос, контакты **с удалением из проекта**, **фильтры по задачам проекта** (статус, поиск), **статистика**, **архив с предупреждениями** |
| **Контакты** | Список, фильтры (**в т.ч. тег** `GET /contacts?tag=`), **быстрые действия** в сетке (карточка, переписка, задачи по контакту, `tel:`), **редактирование карточки**, привязка к проекту, **снятие с проекта из карточки контакта** (по каждому проекту), задачи **с секциями активные / завершённые·отменённые**, переписка, **поиск по сообщениям** в карточке |
| **Коммуникации** | **3 колонки** (диалоги + поиск, переписка + поиск по сообщениям, контекст контакта), MAX sync, задача из сообщения, привязка к задаче, **непрочитанные входящие** в списке диалогов |
| **Поиск** | Единый поиск по задачам, проектам, контактам, сообщениям |
| **Digest** | Сводка по дедлайнам |
| **Уведомления** | In-app: колокольчик, прочитано; **дедлайн скоро / просрочка**, **назначение**, **комментарий**, **упоминание в комментарии** (`@id` / `@email`), **обновление задачи** (исполнитель/автор), **входящее сообщение по контакту** (исполнители активных задач + владельцы/участники связанных проектов); переход в задачу и/или **переписку**; вкладка **`/owner-workspace/notifications`** |
| **Аудит** | Вкладка «История» + история в задаче |
| **Селекты** | Полные каталоги проектов/контактов независимо от фильтров списков |
| **Настройки** | Вкладка и маршрут **`/owner-workspace/settings`**: вид задач, размер страницы списка, окно сводки по дедлайнам, область сводки — **хранение в БД** (`GET/PATCH /me/preferences`) |

## Частично / отличия от формулировок ТЗ

- **URL / меню (ТЗ §6, §16):** один экран с вкладками; **отдельные пути** для разделов: **`/owner-workspace/projects`**, **`/owner-workspace/contacts`**, **`/owner-workspace/tasks`**, **`/owner-workspace/comms`**, **`/owner-workspace/history`**, плюс **`/owner-workspace/notifications`**, **`/owner-workspace/settings`**; **`/owner-workspace`** без query редиректит на **`/owner-workspace/projects`**; **deep-link** `?tab=<slug>&task=<id>` на базовом пути сохранён для совместимости.
- **Роли (§4):** sales/trainer подключены к API и фильтрации; **роли участника проекта:** `member` (по умолчанию) и **`manager`** (ведёт участников: добавление/исключение, не трогает других менеджеров). Назначать роль менеджера могут **владелец проекта** и **admin/owner** портала (`PATCH …/participants/{user_id}`). Архив проекта — по-прежнему только владелец/полный доступ.
- **Уведомления (§7.5):** назначение, комментарий, дедлайны, **обновление задачи** (`task_updated`), **входящее по контакту** (`contact_incoming_message`), **упоминания в комментарии** (`task_mention`: `@id` или `@email@домен`, только если пользователю видна задача; исполнитель/автор не дублируются — им уже «Комментарий»); **нет** email/push; **«задача обновлена»** не дублируется при единственной смене исполнителя; отдельный раздел — **внутри owner-workspace**.
- **Настройки (§7.6):** есть **UI задачника** (персональные умолчания UI); глобальные/системные настройки модуля в ТЗ не детализированы.
- **Карточка проекта (§7.2.2):** блоки в одном диалоге, без вкладок; ~~нет дерева подпроектов и переноса~~ — **сделано:** дерево вложенных подпроектов + выбор родителя и «Перенести» (`PATCH parent_project_id`), проверка циклов на API.
- **Список проектов:** ~~нет явного имени ответственного в карточке~~ — **сделано:** строка «Ответственный» по `owner_id` и каталогу пользователей (фильтр по ответственному как раньше).
- **Список контактов:** ~~в сетке нет компании, тегов, даты последнего взаимодействия~~ — **сделано:** компания, теги, `last_interaction_at` в API (max сообщение / задача / `updated_at`) и в карточке сетки.
- **Задачи по контакту:** ~~нет раздельных секций~~ — **сделано:** активные vs завершённые/отменённые.
- **Коммуникации (§7.4):** ~~нет 3 колонок и поиска по диалогам~~ — **сделано:** 3 колонки, поиск по списку диалогов и по ленте; **непрочитанные:** таблица `owner_workspace_conversation_reads`, счётчик **входящих** после `last_read_at`, сброс при `GET …/contacts/{id}/messages` (и диалог коммуникаций), чип в списке диалогов.
- **Задача:** удаление — `DELETE /tasks/{id}` (только admin/owner); «архив» = статус **Отменена**; у **завершённых/отменённых** нельзя менять поля кроме **статуса** (или полное сохранение при возврате в активный статус).
- **Производительность (§14.1):** пагинация `GET /tasks` (`limit`/`offset`, ответ `items`+`total`) и **TablePagination** в режиме «Список»; канбан/календарь — до 500 задач за запрос с предупреждением при превышении.
- **Аналитика (§17):** **частично:** счётчики по статусам (`GET /tasks/status-counts`) + блок **«Аналитика»** на вкладке «Задачи»: `GET /analytics/tasks-overview` — завершённые за 7/30 дней, среднее число дней до закрытия среди завершённых за 30 дней (по **зоне видимости** пользователя); без расширенных отчётов и разбивки по сотрудникам.

## Прод: миграции Alembic

Бывает рассинхрон: в `alembic_version` уже **0083**, а объекты из более ранних ревизий (например **0079** — `sms_messages.scheduled_at`, таблица `max_messages`) в БД отсутствуют.

**Проверка:** список колонок тем же подключением, что у приложения:

`docker compose exec backend python -c "… information_schema …"`

**Исправление:** догнать схему SQL вручную или откат/накат миграций (осторожно на проде). После правок — `docker compose restart backend` и свежие логи.

## История закрытых этапов в коде

- Этап «контакты в проекте»: API `DELETE …/projects/{id}/contacts/{contactId}`, UI в **проекте** и в **контакте**.
- Архив проекта с предупреждениями; карточка проекта (редактирование + счётчики задач в API).
- Уведомления по дедлайнам (таблица + сервис refresh); сортировка задач; каталоги для селектов.
- Пагинация списка задач: API `OwnerWorkspaceTaskListResponse`, UI `TablePagination` в вкладке «Задачи» (режим список).
- Удаление задачи (`DELETE`), блокировка полей карточки для completed/cancelled; отмена = статус в UI.
- Уведомления: `task_assigned`, `task_comment`; дедуп-ключи; UI вкладка «Уведомления», пункт меню и deep-link на `/owner-workspace/notifications`.
- Deep-link: `/owner-workspace?tab=…&task=…`, переход с `/notifications` на другие вкладки через `/owner-workspace?…`, в адресе появляется `task=` при открытой карточке.
- Карточка контакта: две секции задач + фильтр переписки; коммуникации: диалоги / тред / контекст с кнопкой «Открыть карточку».
- Настройки задачника: таблица `owner_workspace_user_preferences`, API `GET/PATCH /api/owner-workspace/me/preferences`, вкладка + `/owner-workspace/settings`.
- Непрочитанные в диалогах: `owner_workspace_conversation_reads`, счётчик входящих после курсора; в списке проектов — дата обновления карточки.
- Фильтр контактов по тегу (`tag` в API); в карточке проекта — фильтр списка задач по статусу и строке поиска.
- Уведомления: `task_updated`, `contact_incoming_message`; колонка `contact_id` в `owner_workspace_notifications` (0086).
- Счётчики задач по статусам: `GET /api/owner-workspace/tasks/status-counts`, чипы над фильтрами вкладки «Задачи».
- Список контактов: иконки быстрых действий (карточка, коммуникации, задачи с фильтром по контакту, звонок).
- §16: маршруты `App.tsx` для подпутей owner-workspace; синхронизация вкладок с `navigate`; пункт меню «Owner задачник» → `/owner-workspace/projects`.
- §7.5 / §17: `task_mention` при `@id`/`@email` в комментарии; `GET /analytics/tasks-overview`; UI блок аналитики и подсказка у поля комментария.
- §4: миграция **0087** — `owner_workspace_project_participants.role`; менеджер и правила в `owner_workspace_access` / роутере проектов.
