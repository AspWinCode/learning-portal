## 1. Аутентификация

### US-AUTH-01: Вход в систему
**Как** любой пользователь,  
**я хочу** войти по email и паролю,  
**чтобы** получить доступ к своему личному кабинету.

**Тесты:**
| ID | Сценарий | Входные данные | Ожидаемый результат |
|----|----------|----------------|---------------------|
| T-AUTH-01-1 | Успешный вход | Верный email + пароль | 200 OK, access_token в ответе |
| T-AUTH-01-2 | Неверный пароль | Верный email, неверный пароль | 401, "Неверный email или пароль" |
| T-AUTH-01-3 | Несуществующий email | email не в системе | 401, "Неверный email или пароль" |
| T-AUTH-01-4 | Пустые поля | email="" или password="" | 422 Validation Error |
| T-AUTH-01-5 | Неактивный пользователь | is_active=false, верные credentials | 401 Unauthorized |
| T-AUTH-01-6 | Rate limiting | 11 запросов за минуту | 429 Too Many Requests |

**Критерии приёмки:**
- [ ] JWT-токен выдаётся при успешном входе
- [ ] Токен содержит поле `jti` (UUID)
- [ ] Неверные credentials → всегда одно сообщение (нет подсказок)
- [ ] После 10 неудачных попыток за минуту — блокировка

---

### US-AUTH-02: Выход из системы
**Как** авторизованный пользователь,  
**я хочу** выйти из системы,  
**чтобы** мой токен стал недействительным.

**Тесты:**
| ID | Сценарий | Входные данные | Ожидаемый результат |
|----|----------|----------------|---------------------|
| T-AUTH-02-1 | Успешный logout | Валидный токен | 200 OK |
| T-AUTH-02-2 | Токен после logout | Использовать токен после POST /logout | 401 Unauthorized |
| T-AUTH-02-3 | Новый токен после logout | Login → logout → login → GET /auth/me | 200, данные пользователя |
| T-AUTH-02-4 | Logout без токена | Без Authorization header | 401 Unauthorized |

**Критерии приёмки:**
- [ ] Старый токен отклоняется немедленно после logout
- [ ] Запись в Redis blacklist с TTL = оставшееся время жизни токена
- [ ] Новый вход после logout работает корректно

---

### US-AUTH-03: Сброс пароля
**Как** пользователь, забывший пароль,  
**я хочу** сбросить пароль через Telegram,  
**чтобы** восстановить доступ к аккаунту.

**Тесты:**
| ID | Сценарий | Входные данные | Ожидаемый результат |
|----|----------|----------------|---------------------|
| T-AUTH-03-1 | Запрос кода (email есть) | POST /password-reset, email="known@test.com" | 200, "код отправлен" |
| T-AUTH-03-2 | Запрос кода (email нет) | POST /password-reset, email="unknown@test.com" | 200 (не раскрывает наличие) |
| T-AUTH-03-3 | Подтверждение верным кодом | Верный 6-значный код + новый пароль | 200, "Пароль изменён" |
| T-AUTH-03-4 | Подтверждение неверным кодом | Неверный код | 400, "Неверный код или email" |
| T-AUTH-03-5 | Просроченный код | Код старше 15 минут | 400, "Код просрочен" |
| T-AUTH-03-6 | Слабый новый пароль | new_password="12345678" (только цифры) | 422, требования к паролю |
| T-AUTH-03-7 | Старый токен после смены | Старый JWT после /confirm | 401 Unauthorized |

**Критерии приёмки:**
- [ ] Код из 6 цифр, действует 15 минут
- [ ] Код доставляется в Telegram (если привязан)
- [ ] Новый пароль: мин. 8 символов, буква + цифра
- [ ] Старый JWT отзывается при смене пароля

---

**Как** новый родитель,  
**я хочу** установить пароль по ссылке-приглашению,  
**чтобы** получить доступ к кабинету ученика.

**Тесты:**

|----|----------|---------------------|
| T-AUTH-04-1 | Валидный токен, корректный пароль | 200, "Пароль установлен" |
| T-AUTH-04-2 | Просроченный токен (7+ дней) | 400, "Ссылка просрочена" |
| T-AUTH-04-3 | Использованный токен (уже установлен пароль) | 400, "Ссылка недействительна" |
| T-AUTH-04-4 | Слабый пароль | 422, требования к паролю |
| T-AUTH-04-5 | Вход после установки пароля | 200 OK, корректная роль parent |

**Критерии приёмки:**
- [ ] Токен однократного использования (уничтожается после установки)

**Как** Admin/Owner/Sales,

## 3. Ученики

### US-STU-01: Создание ученика
**Как** Admin/Owner/Sales,  
**я хочу** создать профиль ученика,  
**чтобы** начать вести его обучение.

**Тесты:**
| ID | Сценарий | Ожидаемый результат |
|----|----------|---------------------|
| T-STU-01-1 | Создание с родителем | POST /students/with-parent | 201, student + parent созданы |
| T-STU-01-2 | Создание без родителя | POST /students/ без parent_id | 201, ученик без родителя |
| T-STU-01-3 | Создание через конвертацию лида | POST /leads/{id}/convert-to-student | 201, ученик + карточка + родитель |
| T-STU-01-4 | Без ФИО ученика | full_name="" | 422 Validation Error |
| T-STU-01-5 | Тренер пытается создать | POST /students/ с ролью trainer | 403 Forbidden |

**Критерии приёмки:**
- [ ] При создании через `with-parent` — создаётся User(role=parent) если его нет
- [ ] При конвертации из лида — генерируется invite_link для родителя
- [ ] Ученик создаётся в статусе ACTIVE
- [ ] Email родителя отправляется если SMTP настроен

1. Все P0 тест-кейсы модуля пройдены
