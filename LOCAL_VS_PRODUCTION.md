# Локальная разработка и продакшен: один код, разные настройки

Чтобы локальный проект **не отличался** от продакшена по коду, придерживайтесь правила:

- **Код один и тот же** — один репозиторий, одна ветка (например `main`), с неё и деплой, и локальная разработка.
- **Отличаются только настройки** — переменные окружения (файлы `.env`), которые **не коммитятся** в git.

## Что различается (только .env)

| Переменная | Локально | На продакшене |
|------------|----------|----------------|
| **Backend** | | |
| `DATABASE_URL` | `postgresql://...@localhost:5432/learning_portal` | `postgresql://...@db:5432/learning_portal` (или хост вашего сервера БД) |
| `SECRET_KEY` | любой длинный ключ (≥32 символа) | уникальный секретный ключ (≥32 символа) |
| `CORS_ORIGINS` | `http://localhost:3000,http://127.0.0.1:3000` | `https://ваш-домен.ru` |
| `APP_ENV` | не задан или `development` | `production` |
| **Frontend** | | |
| `REACT_APP_API_URL` | `http://localhost:8000` | `https://api.ваш-домен.ru` (или URL вашего API) |

Файлы `.env` уже в `.gitignore` — в репозиторий попадает только шаблон:  
`backend/.env.example` и `frontend/.env.example`.

## Как держать локаль и продакшен в sync

1. **Один репозиторий**  
   И локальная папка, и код на сервере — из одного и того же репо (например GitHub).

2. **Перед деплоем на прод**  
   - На сервере: `git pull` из той же ветки, с которой работаете локально.  
   - На сервере: свои `.env` с продакшен-значениями (не перезаписывать их при деплое).  
   - При необходимости: миграции БД (`alembic upgrade head` или свой скрипт).

3. **Локально**  
   - После `git pull` у вас тот же код, что и на проде.  
   - Локальные `backend/.env` и `frontend/.env` — только для разработки (localhost, локальная БД).

4. **Не делать**  
   - Не держать «отдельную версию» кода для прода — все фичи и правки вести в общем репо и выкатывать на прод из него.  
   - Не коммитить `.env` с паролями и секретами.

## Чеклист деплоя (напоминание)

- [ ] На сервере выполнен `git pull` из нужной ветки.
- [ ] На сервере в `backend/.env`: продакшенские `DATABASE_URL`, `SECRET_KEY`, `CORS_ORIGINS`, при необходимости `APP_ENV=production`.
- [ ] На сервере при сборке фронта задан `REACT_APP_API_URL` на прод-API (или в `frontend/.env` при сборке).
- [ ] Миграции БД применены (`alembic upgrade head` или эквивалент).
- [ ] Перезапущены backend и (при необходимости) frontend.

Если следовать этому, локальный проект и продакшен отличаются **только настройками**, а не кодом.
